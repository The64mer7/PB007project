Non-functional requirements:

  1. System will process received location within 1 second
  2. Car is sending its position to the system every second
  3. Car waits for clients for 15 minutes

 Register : Use Case

An unregistered user creates an account by providing an email address, full name, date of birth, phone number, and choosing a password. After successful registration, the user can access the system as a registered user.

 Search for available cars : Use Case

Description:

        The user searches for a suitable car or ride from point A to point B, with the option to select additional accessories for premium users.

Primary actors: User

Secondary actors: -

Preconditions: -

Main flow:

        User clicks the button to search for a ride

        User inputs pickup point, destination, pickup time, number of passengers

        if User is Premium User{

                User gets the option to input wanted equipment}

        System validates all fields

        System searches available rides that fit the User's requirements

        System creates a route from pickup to destination

        System displays available rides to the User

Post-conditions:

        Available suitable rides are displayed to the user

Alternative flow:

        No cars are available:

                User gets the option to change their requirements

       User logs out:

                Action gets canceled

        No route from pickup point to destination has been found by the system:

                User gets the option to change their requirements

 Order ride : Use Case

Description:

        The Registered User orders a car by selecting an available ride from the search results and completing the payment process.

Primary actors: Registered User

Secondary actors: Payment provider

Preconditions: The user searched for a ride and at least one ride was provided

Main flow:

        Registered User chooses a ride from the list of available rides

        Registered User is asked to confirm the selected ride

        if Registered User cancels the selection{

                Order ride()}

        else{

                Registered User is asked to fill in card information

                Payment provider Processes payment

                if payment successful{

                        Car sets availability to unavailable

                        System calculates route

                        System sends route to car}}

Post-conditions:

        Car is unavailable, Firm received money

Alternative flow:

        Payment fails:

                User receives an option to retry payment or cancel ride

       User logs out before payment:

                Action gets canceled

 Create asset : Use Case

The manager adds a new asset to the system by entering its relevant details. The system stores the new asset record for future management and use.

 Edit asset : Use Case

The manager modifies the details of an existing asset. The system saves the changes to ensure the asset information remains current.

 Delete asset : Use Case

The manager removes an asset that is no longer needed or available. The system updates its records to reflect the removal.

 View statistics : Use Case

The manager can access statistical information about system operations and asset usage. These statistics help monitor performance and support management decisions.

 Report arrival : Use Case

The car's system reports that it has arrived at the pickup location. The system records the arrival information so that the route status can be updated.

 Set availability : Use Case

The car sets its status as available when it isn't currently driving passengers or en route to a pickup location or when its battery is above 40% and as unavailable otherwise.

 Report technical issue : Use Case

The car reports a technical problem or malfunction. In response, the system modifies the route or finds a suitable place to park if needed.

 Report location : Use Case

The vehicle sends its position to the system every second. 

 Report battery status : Use Case

The car sends its battery status to the system every second. Whenever the battery charge drops below 40%, and the vehicle is not carrying out any order at the moment, the system will navigate the vehicle to the nearest free charging station.

 Choose car accessories : Use Case

During search, premium users can choose additional car accessories, such as entertainment systems, comfort accessories, etc.

 Send notifications : Use Case

The system sends notifications to relevant users about the status of their route, such as changes of route, cancellations, or vehicle arrival.

 Calculate route : Use Case

All routes to the destinations are computed by the system and then sent to the vehicle. The route is computed based on the current position of the vehicle and the traffic situation. The route is represented by a collection of waypoints that the autonomous car is able to follow.

 Cancel route : Use Case

If the passengers don't get onboard the vehicle within 15 minutes after it arrives to the pickup point, the system cancels the order.

 Send refund : Use Case

The system sends back the money for the canceled order but deducts a cancellation fee.

 Save data : Use Case

The system saves all data (orders, car information, routes, etc.) every second.

 Process payment : Use Case

The system processes payment for a ride or a premium membership. It communicates with the external payment provider to handle the transaction and determine its outcome.

 Find a suitable place to park : Use Case

When the car isn't carrying passengers and is available, the system finds a place to park and navigates the car there.

 Review order history : Use Case

Registered users can view their previous orders and rides. The system displays relevant historical information, such as booking details and ride records.

 Provide state of the traffic : Use Case

The system obtains traffic information from an external traffic information provider. It uses this information to plan the routes of the cars.

 Unsubscribe from premium membership : Use Case

A premium user can cancel their premium subscription. The system updates the user's membership status and deletes their access to premium features.
